## A. USB device mode on USB3-capable DWC3 (priority a)

### A1. anonbeat1/ios-sweet, Nothing Phone (1) "Spacewar", SM7325 (yupik)  <- the only confirmed hardware success on a USB3-capable Qualcomm DWC3
Patch xnu/patches/0091-sweet-spacewar-usb-net-smmu.patch, commit https://github.com/anonbeat1/ios-sweet/commit/ef3408d73 ; fixes https://github.com/anonbeat1/ios-sweet/commit/437941ceb (map GCC 0x1f0000), https://github.com/anonbeat1/ios-sweet/commit/99ddd1117 (read only cross-SoC CBCRs), https://github.com/anonbeat1/ios-sweet/commit/1035e53d5 (SMR reuse, the actual fix); milestone note https://github.com/anonbeat1/ios-sweet/commit/4a9a45ef3 .
Hardware facts they measured (NOTES.md, "0091 usb boot" entries): DWC3 GSNPSID 0x5533330a (v3.30a), HS PHY is snps-femto @0x88e3000 (not QUSB2), GDSC/clocks left ON by ABL, DWC3 at 0xa600000. Result: CDC-ECM enumerates on a Mac as en7, `ping 192.168.7.2` 0.9-2.7 ms, live UDP log works. Same sweet_usb.c gadget code as upstream (0073-0076): `DCTL=CSFTRST` ("soft reset done after 1 ms"), own event buffer, DCFG, DEVTEN=7, ep0 DEPSTARTCFG/SETEPCONFIG/SETTRANSFRESOURCE, DALEPENA=3, setup TRB, QSCRATCH VBUS override. i.e. on SM7325 the plain upstream sequence incl. DCTL soft reset works with NO PIPE-clock or PHY touching. The only functional additions were:
 1. Board params from ADT node /sweet-usb (gdscr-off 0xf004, master-off, cfgnoc-off, no-qusb2, smmu-sid).
 2. The controller sits behind apps_smmu (live DT `iommus <0x1a 0xe0>`, SID 0xe0). The first DMA (STARTTRANSFER of the ep0 SETUP TRB) reset the SoC (hypervisor turns SMMU global fault into reset). Fix = new bsd/dev/sweet_smmu.c: map base 0x15000000 (apps_smmu, size 0x100000); build a stage-1 context bank (CBAR type1 `1<<16|0xf<<12|3<<8`, CBA2R=1 VA64, TCR `25|1<<23`, TCR2 `7<<15|2`, MAIR0 0x44, TTBR0 -> 1 GiB-block identity map of DRAM 0x80000000..0x27fffffff, Normal NC, SCTLR `CFIE|CFRE|AFE|TRE|M`); then for the stream ID find an *existing* valid SMR matching the SID (ABL's fastboot already has one) and repoint its S2CR (`S2CR = cb index`, type 0 = translate) instead of adding a duplicate SMR (a second matching SMR = stream-match conflict = reset). This last detail (reuse ABL's SMR) is what finally made DMA survive.
 Applicability to SDM845: DWC3 USB1 at 0xa600000 is behind apps_smmu too (Linux sdm845.dtsi: `iommus = <&apps_smmu 0x740 0>`, from memory, please verify against the beryllium DTB). Poco F1 has a QHEE hypervisor, so unmatched streams may reset the SoC. This does NOT explain your CMDACT-stuck-on-SETEPCONFIG (that is a register command, no DMA), but you will hit it right after ep0 works at the first STARTTRANSFER. Reuse sweet_smmu.c almost verbatim (change SID, SMMU base is 0x15000000 on sdm845 as well, context banks 0..n).
 Their series after USB: 0092 (configd network, see D1), 0093 (log without loss).

### A2. Lrdsnow/ios-froggerpro, Nothing Phone (4a) Pro, SM7750 "kera" (DWC3 USB3-capable, eUSB2 PHY): shim USB CDC-ACM console works on hardware
File shim/usb.c (header comment) ; docs in NOTES.md "Update 2026-10-18 (evening): USB console WORKS on the phone" ; xnu port: https://github.com/Lrdsnow/ios-froggerpro/commit/e762cc500 (0093), GCC-offset fix https://github.com/Lrdsnow/ios-froggerpro/commit/3cb15337d (0097). The xnu path (0093+) was not yet shown to enumerate when I read it; the shim path did.
Sequence in shim/usb.c usb_init() (SS never used; HS forced):
```
GDSC 0x139004 / CBCRs (master 0x139018 sleep 0x139028 utmi 0x13902c cfgnoc 0x139090 aggre 0x139094) checked, enabled if OFF
DCTL &= ~RUN_STOP; wait DSTS.DEVCTRLHLT (bit22)
DCTL = CSFTRST (bit30); wait clear               <- soft reset DOES complete there
zero 4K event buf; GEVNTADR/SIZ(1<<31 | size)/COUNT
DCFG &= ~(7 | 0x7f<<3)          # DEVSPD=0 (HS), addr 0
DEVTEN = 7
DEPSTARTCFG ep0; SETEPCONFIG ep0 (par0=512<<3, par1=(1<<8)|(1<<10)); SETTRANSFRESOURCE; same for ep1 (+ (1<<25) dir bit field)
DALEPENA = 3; arm SETUP TRB
QSCRATCH(0xf8800) HS_PHY_CTRL(+0x10) |= (1<<20)|(1<<28); SS_PHY_CTRL(+0x30) |= (1<<24)
DCTL |= RUN_STOP
```
Also notes: MMU off (all RAM Device memory, so no cache maintenance) and DMA by physical address relying on SMMU stream (SID 0x40 for kera) staying in ABL's pass-through state. Its xnu 0093 includes shim usb_stop() (DEVTEN=0, RUN_STOP off, GEVNTSIZ masked) before jumping to the kernel so the shim's event buffer is not DMA'd into. Useful pattern for you if a shim stage exists.
Applicability: confirms the register recipe, but SM7750's PHY differs, so again it does not explain the SDM845 hang by itself.

### A3. arielTROY/ios-sweet, Pixel 10a "stallion" (Tensor G4, Synopsys DWC_usb31, not Qualcomm), the most informative hint for your CMDACT-stuck symptom
Patch xnu/patches/0084-stallion-usb.patch, commit https://github.com/arielTROY/ios-sweet/commit/77e41d3e0 ; shim version in shim/usblog.c ep_cmd() (commit https://github.com/arielTROY/ios-sweet/commit/3aff2674c, "bare-metal DWC3 CDC-ACM gadget enumerates on the Mac"). Link-local ue0 + broadcast live log: 0085 https://github.com/arielTROY/ios-sweet/commit/292dd1fb6, 0086 https://github.com/arielTROY/ios-sweet/commit/96c1eeb06.
Key idea (their comment cites DWC databook 6.3.2.5 and Linux dwc3_send_gadget_ep_cmd): **no endpoint command may be issued while the USB2 PHY is suspended**. They wrap EVERY DEPCMD with:
```
phy = rd(GUSB2PHYCFG0 @0xc200);
wr(GUSB2PHYCFG0, phy & ~(SUSPHY(1<<6) | ENBLSLPM(1<<8)));
 ... write DEPCMDPAR0-2, DEPCMD = cmd|CMDACT, poll CMDACT ...
wr(GUSB2PHYCFG0, phy);   // restore
```
and they save/restore a set of globals across DCTL.CSFTRST (GUSB2PHYCFG0 0xc200, GUSB3PIPECTL0 0xc2c0, GSBUSCFG0/1 0xc100/0xc104, GUCTL 0xc12c, GUCTL1 0xc11c, GTXFIFOSIZ0-3 0xc300+4n, GRXFIFOSIZ0 0xc380) because the reset reloads defaults (default GUSB2PHYCFG has SUSPHY=1), then wait 50 ms (DWC_usb31<=1.80a) and keep the host disconnected >= 100 ms. They also cleared the HSI0 SysMMU CTRL_VM(0) bit0 (bypass) before DMA. Enumerated on a Mac.
**My hypothesis for SDM845 (not verified by any fork, derived from this + Linux source):** after DCTL soft reset the core reverts to GUSB2PHYCFG.SUSPHY=1 (and GUSB3PIPECTL.SUSPHY(bit17)=1 default). With the QMP SS PHY/PIPE clock not running and the HS PHY in suspend, the core's command engine never completes (CMDACT stuck). Try, before the first DEPCMD: clear GUSB2PHYCFG0 bits 6 and 8 (and for good measure GUSB3PIPECTL0 bit 17), and keep them cleared (or wrap every command like stallion). Also consider the other Linux quirk bit GUCTL1 bit 26 (DEV_FORCE_20_CLK_FOR_30_CLK, "snps,dev-force-20-clk-for-30-clk") for USB2-only operation without a PIPE clock, this one is purely from the Linux header, not from any fork. Since your boots 0084-0088 never mention GUSB2PHYCFG/GUSB3PIPECTL, this is the cheapest next experiment (log GUSB2PHYCFG0/GUSB3PIPECTL0 before and after reset to see SUSPHY state).

## Summary of what is most useful to try first (SDM845 USB)
 1. Before any DEPCMD: clear GUSB2PHYCFG0 (0xc200) SUSPHY bit6 + ENBLSLPM bit8 (and GUSB3PIPECTL0 0xc2c0 bit17), either permanently or around every command (arielTROY stallion 0084). Log GUSB2PHYCFG/GUSB3PIPECTL/GCTL/GUCTL1 pre and post CSFTRST. If you keep soft reset: wait >=50 ms after it, and re-write the pre-reset values of GSBUSCFG0/1, GUCTL, GUCTL1, GTX/RXFIFOSIZ, GUSB2PHYCFG0, GUSB3PIPECTL0.
 2. When ep0 works, expect SoC reset on first DMA: copy anonbeat1's sweet_smmu.c with SMR reuse (stream IDs for USB1 on sdm845 are in the DTB `iommus`).
 3. Keep your QSCRATCH VBUS override (0074 equivalent, also used by all forks) and the UTMI-as-PIPE-clock selection (not used by any fork, since the others' PIPE clocks survived ABL; no fork has solved a "QMP PHY down" case).
