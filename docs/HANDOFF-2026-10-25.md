## 0. Rules that apply to everything

- **Flashing.** Every flash or boot goes through the Bergamota queue (`apps/Bergamota/scripts/bergamota`), with the user's
  explicit OK for each one.
  - Only `boot`, `userdata` and `logo` are ever written. Never modem, persist, bluetooth or dsp.
  - Reading those partitions also needs the user's OK.
- **Commands.** Every command runs under a 15 s timeout (`timeout 13` on the phone); long work goes in the background.
  - Keep at least 10 GB free on the Mac. Don't start Docker Desktop.
- **Installs on the phone.** Write to a temp file, then `mv`. Never `cp` over a mapped dylib.
- **Out of git and public places:** Apple files, Qualcomm firmware, dumps and serials.
  - Boot images that contain the `gpufwz` ADT (GPU firmware) are never published.
- **Commits.** New work goes on `develop` (Bergamota) or `main` (Chlorophyll). No co-author trailers.
- **Rules for a future iOS 26 session**, learned the hard way:
  - Never restart backboardd by hand. It breaks touch, and 3–4 restarts in a few minutes make launchd shut the system down
    (ending in the "initproc exited" panic). Chlorophyll's own watchdog restarts it once and then writes `bgmtl-bb.off`.
  - Never put SpringBoard on Chlorophyll's allow list with `chlorophyll=1`. It crash-loops, and launchd shuts the phone down.

The four Chlorophyll fixes for iOS 26:
- **Command-buffer slots** (3d8f656): iOS 26 allows a queue 64 command buffers in flight, and ours never gave their slots back.
- **IOSurface pitch:** surfaces whose row pitch isn't 64-byte aligned become a texture of our own memory, refreshed from the
  surface.
- **Dynamic threadgroup memory:** a buffer sized at dispatch gets the Adreno's full 32 KB.
- **`get_read_sampler`:** support for iOS 26's texture reads.

## 3. Wi-Fi and Bluetooth

**Bluetooth on iOS 18 works** on combo9 and later: bluetoothd stays up, it's PoweredOn, and Settings lists nearby devices. That
took patches 0238 (AKS key wrap), 0239 v7 (HCI compatibility) and 0250 (Skywalk privileges; without it, connecting crashed
bluetoothd). All three are merged into develop, and the details are in `docs/WIFI_BT_IOS18.md`. The patches are also in
`ios26`, but Bluetooth on iOS 26 hasn't been re-tested. The BT firmware and ADT node are in `tools/adt-bluetooth.py`, with the
firmware supplied via `RENEGADE_BT_FW` (never committed).

**Wi-Fi on iOS 26** (branch `wlan26`, merged into `ios26`; doc `docs/WIFI_IOS26.md`). **Paused** by the user so the GPU work
could go first.
- **The iOS half is done.** iOS 26 has no IO80211 kext: Wi-Fi is a DriverKit dext. wifid only matches IOKit properties, and the
  framework falls back to ioctls, so a kernel stand-in is enough:
  - 1100: the stand-in (`sweet80211=1`);
  - 1101: fixes from boot 23;
  - 1102: the synthetic network (`sweet80211=2`);
  - 1103: the supported-channel list Settings needs before it scans.

  On boot 29 Settings → Wi-Fi listed "Bergamota-test" (user-confirmed), and `sweetwifi scan` returns it. Joining fails by design:
  there's no real radio behind it.
- **The chip half is in progress** (doc sections 5–5.4):
  - Boot 30's read-only probe (`sweetwlan=3`) was clean: modem firmware, board data and EFS are present.
  - 1104 fixed the SMEM table parsing.
  - 1105 adds the power-domain votes (cx, mx, mss) and 1106 the modem boot step (MSS/MBA, following Linux). Both were reviewed
    against Linux.
  - The first run (boot 32) and a traced re-run (1107, boot 34) **froze while copying the modem boot loader**. The copy into
    0x96900000 happened after the modem was already powered and out of reset.
  - **1108** moves the copy before any modem hardware access, as Linux does. It's merged into `ios26` but **has not run**.
- **Next:** the 1108 copy-only run, at the phone, with the user's OK. Then power-up and the MBA/MPSS handshake. Then WLFW, the
  chip's firmware service. Then joining a real network.
- **Rule:** nothing writes modem, persist or bluetooth data. The modem steps only read those partitions and call TrustZone (a
  stuck SoC worst case reboots the phone).

**Wi-Fi on iOS 18** stays blocked: it needs the same chip half.

## 4. Renegade in Rust (develop, `tools/renegade-rs`, PR ry-diffusion/Bergamota#4, merged)

A Rust crate (library plus the `renegade-rs` CLI; the library builds for wasm32). It replaces the Python Renegade stage by stage,
and each stage is tested against the Python output. The table is in `tools/renegade-rs/README.md`; 23 tests run with
`cargo test --release` (needs python3, plus macOS for the hdiutil/fsck_hfs/codesign checks).

- **Ported, identical to the Python:**
  - sparse images (`img2simg` / `simg2img`);
  - the HFS+/HFSX reader;
  - `pacstrip` (rewrite and `--sign`, the latter byte-identical on all 3,222 re-signed Mach-Os of the iOS 26 root);
  - `fixupcheck`, the owner pass, trim and the owner map;
  - an HFS writer (`mkhfs`, `rebuild`; fsck clean);
  - plists (byte-identical on 426 plists of the iOS 26 root);
  - most `root_tweaks18` tweaks, and the `root` command (copy-stage fixes, tweaks, owners, the Mach-O stage, seal, sparse).
- **Not ported yet:**
  - ldid signing (Linux);
  - the tweaks that install prebuilt tools with host steps (ssh, BlueTool stub, PosterBoard/sweetfp, bgmtl, bglrender, the
    first-boot job, sweetprefs);
  - the console job and the jailbreak stage;
  - IPSW/AEA extraction and APFS volumes;
  - the shared-cache stage (`pacstrip_cache.py`, still changing on `ios26`);
  - `simg_putfile.py`;
  - boot images (`mkboot-full.sh`).
- **Python stays the working path** until the Rust port covers everything. The port's reference point is `ios26` at 6a66010.

## 5. Web flasher (develop, `apps/web`, PR ry-diffusion/Bergamota#3, merged)

A Svelte 5 + Vite site served by a Cloudflare Worker at **bergamota.zesmoi.com.br**: the landing page at `/`, the flasher at
`/flash/`. The first deploy was 2026-10-24, with the user's OK. `npm run deploy` needs `wrangler login` on the account that owns
the `zesmoi.com.br` zone. Tests: 11 unit tests (`npm test`); `npm run build` builds the site.

- **"Flash an image" works:**
  - WebUSB fastboot (`src/lib/fastboot.ts`);
  - a hard allowlist of `userdata`, `boot` and `logo`;
  - getvar/download/flash/reboot only;
  - sparse images streamed in pieces of at most 512 MiB;
  - a product check.
- **"Patch IPSW + flash" is the default path but can't run yet.** The IPSW step checks the file against Renegade's profiles
  (`src/lib/profiles.ts`), then points to the Python `renegade root` until the Rust/WebAssembly patcher can do the job in the
  browser (phase 3).
- **Never hosted:** Apple files and Qualcomm firmware. Boot images could be offered only without the GPU-firmware ADT.
- **Design:** the Newton identity (`apps/web/DESIGN.md`, `PRODUCT.md`).
